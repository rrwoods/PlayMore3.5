[ODRIC 9] Ability-substitution effects

Some way of telling a statistic "when you calculate your value, if you would add the value of X, instead add the value of Y".  Some recursion magic is probably helpful here; i.e., when you initiate the call at the top level you get to specify some substitutions, and derived calculations can add to those substitutions as necessary.  When reporting the explanation, the text should reflect the substitution (i.e. someone applying DEX with Weapon Finesse shouldn't get an explanation that mentions their STR mod)

[ESOTERIC] "Upgrade" effects.

By this I mean, an effect that says "get [benefit].  if you already had [benefit], instead get [other benefit]."  This isn't doable in the current system with a simple conditional, because the first part of the effect will satisfy the conditional and erroneously grant the secondary benefit.

For an example of this, there's the uncanny dodge class feature, which frequently comes with "if you already have this, get improved uncanny dodge instead".  Another example is the vestige Leraje's "Weapon Proficiency" ability, which grants four specific proficiencies, but for each of them you already have, you instead get a +1 competence bonus on attack rolls.

[ESOTERIC] Multiform support (e.g. wild shape, polymorph, hengeyokai)

This needs to be able to overwrite any number of assigned ability scores.  Possibly via ability-substitution effects?  Like, for example, the "bear wild shape" form can set up a new stat called "Bear STR", and then set up an effect that says "when computing STR score, swap Assigned STR for Bear STR".

This surely varies from DM to DM, but for forms that also ignore your level increments (RAW polymorph works this way), we can do another ability-substitution, replacing the stat value that represents the level increment (which we'd need to set up) with one that's always zero.

[USABILITY] Formalize DR, SR, resistances

Right now they are text and it's up to the player to determine how conflicting ones might interact. For all three of these things, the rules are that the highest applies.

Start with SR. It's "simple" since it's just a number -- but I might need a new NumberPool concept to take the greatest value from?

For resistances, it's like SR except that each energy type gets its own pool, and again apply the best.

For DR, it's like resistances, except that the tag is the thing that overcomes the DR instead of the thing it applies against (which gets weird with DR/--.)
