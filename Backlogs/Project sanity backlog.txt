Once IJsonable has a ReadJson method that reads json into an empty T, we can write:

        public static void FromJson<T>(this List<T> list, string keyName, JObject json) where T : IJsonable {
            if (json[keyName] != null) {
                list.AddRange(json[keyName].Select(x => new T().ReadJson(x)));
            }
        }

When originally integrating the UI with the stats engine, I introduced the controller and had it contain a character, but I made that character public and had the UI interact with it directly.  My reasoning at the time was that "going through the controller's character is the same as going through the controller".  In retrospect though, if/when a UI rewrite happens I will probably end up tripping over some of the shortcuts made as a result.

Make Controller.character private, and write accessors/mutators for all the stuff that breaks in the UI as a result, possibly introducing some convenience in the process where it looks warranted.
